## 背景

TASK-012 已能把内存中的评测样例和现成结果汇总为脱敏的 `BatchEvalReport`，但一次运行尚不能从固定输入重现，也没有可保存和比较的运行记录。只保存通过率会丢失逐条失败证据；只保存报告而不记录输入版本，则无法判断两次运行是否可比。

本任务建立一条**完全离线**的运行路径：读取公开的样例与结果文件，复用已有加载器和批量评分器，保存带输入指纹与评分规则版本的 JSON 报告。重点是输入合同、失败边界、可复现性和文件写入，不生成模型结果。

## 学习目标

完成后，学习者应该能够：

- [ ] 解释评测样例、现成结果、评分规则版本和最终报告各自的职责。
- [ ] 独立设计文件输入的校验顺序，以及失败时是否创建报告文件的行为。
- [ ] 说明输入文件哈希能证明什么、不能证明什么；解释确定性报告与模型输出非确定性的区别。
- [ ] 用固定数据重跑一次评测，并根据保存的逐条结果定位失败样例。

## 功能要求

### 1. 离线输入

- 在 `exercises/task_008_llm_evaluation/` 下新增一个运行模块，提供公开函数 `run_offline_evaluation(case_path, outcome_path, report_path, *, scorer_version)`；路径接受 `Path | str`，返回 TASK-012 的 `BatchEvalReport`。
- `case_path` 使用现有 `verify_evaluation_set()` 加载 JSONL 样例，不另写一套样例校验。
- `outcome_path` 为 UTF-8 JSONL。每条非空行是一个对象，恰有 `case_id` 和 `result` 两个字段；`result` 为符合 `AnalysisResult` 的对象或显式 `null`。空行可跳过；重复 ID、缺失字段、多余字段、无效 JSON 或无效结果必须拒绝。`case_id` 使用与 `EvalCase.case_id` 一致的非空约束。
- 完成文件解析后调用 `evaluate_batch()`；由它检查样例与结果的 ID 对应关系和计算分数。不调用模型、不读取 API Key、不修改输入文件。
- 对无效输入抛出安全异常，指出文件类别和行号或 ID 不一致的类别即可；异常文本不得包含原始对话、原始模型输出或 JSON 行内容。

### 2. 运行报告

- 保存一个 UTF-8 JSON 对象，顶层包含固定的 `schema_version=1`、非空的 `scorer_version`、两个输入文件各自的 SHA-256 十六进制摘要，以及完整的 `BatchEvalReport`。哈希基于文件原始字节计算；报告不得包含输入路径、原始对话、原始模型输出或异常文本。
- 相同输入字节和相同 `scorer_version` 重跑时，报告 JSON 内容必须一致；不要加入当前时间、随机 ID 或机器路径。排序和缩进方式可自行选择，但必须稳定，且能被标准库 `json.loads()` 读取。
- `scorer_version` 是人为声明的规则版本，不得由哈希冒充；文档或代码注释须说明：文件哈希只能标识输入字节，不能证明评分代码、提示词或模型配置相同。
- 写入前完成所有输入校验、批量评分和报告序列化。若目标文件已存在，抛出 `FileExistsError`，不覆盖已有报告。输入或评分失败时不应创建目标报告文件。
- 成功写入后返回内存中的 `BatchEvalReport`。不新增 CLI；用简短的本地示例或手动验证记录展示如何调用函数和读取报告。

## 边界情况

- 空输入文件是合法空批次；只有一侧为空而另一侧有 ID，属于输入不一致。
- 结果文件中显式 `null` 是本次没有有效结果；完全缺少某个 ID 是输入错误。
- `scorer_version` 为空白应拒绝；版本号变化会改变报告内容，但不会改变既有评分规则。
- 输入包含非 ASCII 文字时，读取和写入仍使用 UTF-8；错误消息不回显原始内容。
- 文件哈希用于识别输入版本，不代替数据集审查，也不说明真实模型是否被调用。
