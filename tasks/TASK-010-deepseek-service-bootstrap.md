## 背景

TASK-009 已有可注入分析器的 `POST /analyses`，TASK-007 已有结构化 DeepSeek 调用，但目前没有可本地启动的装配入口。曾为浏览器测试临时添加 GET 路由和真实客户端构造，随后因 URL 暴露与请求语义问题移除。本任务沿现有 POST 接口，把配置、客户端和业务函数接起来，并能在本机启动服务。

学习重点是区分模块导入、应用创建和收到请求三个时点，保持密钥安全和默认测试离线。

## 功能要求

### 1. 配置与装配

- 生产代码放在 `exercises/task_010_service_bootstrap/`。
- 提供公开零参数应用工厂，可由 Uvicorn `--factory` 调用并返回 TASK-009 的 FastAPI 应用。
- 模块导入时不读取密钥、不创建客户端、不访问网络。
- 应用工厂读取 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL`；缺失或纯空白时，以明确且不含密钥的配置错误停止创建应用。
- 可选的 `DEEPSEEK_MAX_OUTPUT_TOKENS` 默认 `2000`；提供时必须是整数且不小于 TASK-007 的下限 `16`。无效值在创建应用时产生明确的配置错误。
- 使用现有 OpenAI Python SDK 创建指向 DeepSeek Responses API 的客户端，复用 TASK-007 的 `AnalysisSettings` 和 `structured_analysis`。
- 将接收对话字符串、返回 `AnalysisResponse` 的同步分析函数交给 TASK-009 的 `create_app`。现有 `POST /analyses` 合同保持不变。
- 应用创建阶段不发送模型请求；只有合法的分析请求才调用分析器。
- 在 `requirements.txt` 中直接声明 Uvicorn 运行时依赖。

### 2. 本地运行说明

在新增模块旁提供简短运行说明，至少包含：

- 环境变量名称、用途与有效范围；示例密钥只能是占位文本。
- 使用 `python -m uvicorn` 和 `--factory`，仅监听 `127.0.0.1` 的启动命令。
- 查看 `/docs` 或 `/openapi.json` 的方式，以及停止服务的方法。浏览器交互测试通过 `/docs` 发起 POST，不增加 GET 分析路由。
- 真实 `POST /analyses` 会调用付费 API；是否执行由学习者显式决定。若执行，只使用一条无敏感信息的合成对话，并记录脱敏的命令与结果。

- 不复制 TASK-007 的提示词、Schema 或请求逻辑，不复制 TASK-009 的路由。

## 边界情况

- Key、模型名缺失或只含空白。
- token 上限为空字符串、非整数、低于 `16` 或恰好为 `16`。
- 模块被导入但从未创建应用；应用已创建但从未收到请求。
- 合法 POST 请求和被 Pydantic 拒绝的请求。
