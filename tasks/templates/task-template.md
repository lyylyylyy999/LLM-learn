# TASK-XXX — 任务名称

- **难度：** L1 / L2 / L3 / L4 / L5
- **预计有效编码时间：** 30 分钟至 3 小时
- **建议分支：** `learn/task-XXX-short-description`
- **状态：** 待确认 / 进行中 / 代码审查 / 已完成

## 背景

说明真实场景、需要解决的问题，以及为什么这个任务值得学习。

## 学习目标

完成后，学习者应该能够：

- [ ] 使用自己的话解释核心机制。
- [ ] 独立实现并验证目标行为。
- [ ] 说明关键设计取舍与失败场景。

## 前置知识

- 开始前必须理解的概念。
- 最少必要的阅读、文档或小实验。

## 功能要求

1. 明确、可观察的功能需求。
2. 输入、输出和错误行为。
3. 需要保留的接口或兼容性要求。

## 约束

- 本任务暂时禁止或限制使用的框架、库或捷径。
- 必须自行实现或重点练习的部分。
- 非功能约束，如类型、日志、性能或安全边界。

## 验收标准

- [ ] 给定具体条件时，系统产生明确结果。
- [ ] 失败输入返回预期错误类型或状态。
- [ ] 验收方式可通过命令、测试或演示复现。

## 测试要求

- [ ] 正常路径。
- [ ] 预期失败路径。
- [ ] 关键边界条件。
- [ ] 针对已修复缺陷的回归测试（如适用）。

记录需要执行的测试命令和预期结果，但不要预先给出完整实现。

## 边界情况

- 空值、缺失值、边界大小或非法格式。
- 重复请求、部分失败、并发或外部依赖失败（按任务范围选择）。

## 进阶任务

可选的进阶目标。进阶任务不属于基础完成定义，不应扩大核心任务范围。

## 审查问题

1. 为什么选择当前设计或数据结构？
2. 哪些失败可以恢复，哪些应该直接暴露？
3. 如何证明实现正确，而不只是“运行过一次”？
4. 如果数据量、并发或依赖延迟增加，哪里会先出现问题？

## 完成定义

- [ ] 功能要求和验收标准全部满足。
- [ ] 要求的测试已编写并通过，实际命令与结果已记录。
- [ ] 边界情况已处理，或未处理项及原因已明确记录。
- [ ] 代码审查中没有未处理的严重问题；主要问题已修复或有明确风险说明。
- [ ] 学习者能回答核心审查问题。
- [ ] 已检查任务分支相对 `develop` 的差异，变更范围与任务一致。
- [ ] 已获得建议提交信息；提交、推送、合并仍由学习者决定。
- [ ] 有实际代码量时，已完成任务复盘。
