# TASK-005 — 受限并发的异步批处理器

- **难度：** L2
- **预计有效编码时间：** 150–180 分钟
- **开发分支：** `develop`
- **状态：** 已完成

## 背景

LLM API、嵌入服务和远程数据接口通常属于 I/O 密集型操作。逐个等待请求会浪费大量时间，但一次性无限并发又可能耗尽连接、触发速率限制或给外部服务造成过大压力。

本任务要求实现一个受并发上限控制的异步批处理器。它接收一组输入和一个异步 worker，并为每项输入生成结构化成功或失败结果。任务不访问真实网络，重点是理解协程、任务调度、受限并发、结果顺序和异步失败隔离。

## 学习目标

完成后，学习者应该能够：

- [ ] 解释协程对象、`await` 和并发任务之间的区别。
- [ ] 使用异步同步原语限制同时运行的 worker 数量。
- [ ] 保持输出顺序与输入顺序一致，而不依赖完成顺序。
- [ ] 隔离单项普通异常，使其他输入仍能完成。
- [ ] 在不访问真实网络和不依赖真实等待的情况下测试异步并发行为。

## 前置知识

- `async def` 调用后返回协程对象，只有被等待或调度后才会执行。
- `await` 会暂停当前协程，让事件循环运行其他可继续推进的任务。
- 并发不等于并行；单线程事件循环可以让多个 I/O 等待过程交错推进。
- `asyncio.Semaphore` 的基本语义。
- `asyncio.gather` 的结果顺序与异常行为。
- `Awaitable[R]`、`Callable[[T], Awaitable[R]]`、`TypeVar` 和泛型数据类。

建议先完成三个最小实验：

1. 创建两个包含 `await asyncio.sleep(0)` 的协程，观察顺序执行和并发执行的日志顺序差异。
2. 用 `asyncio.Semaphore(2)` 包围一段协程代码，记录当前活跃数量和峰值。
3. 让多个协程以不同顺序完成，观察 `asyncio.gather` 返回结果的排列顺序。

## 功能要求

### 1. 项目位置

实现代码放在首次实现时创建的 `exercises/task_005_async_batch/` 目录中，测试放在 `tests/test_task_005/`。

保持模块结构最小，不修改 TASK-001 至 TASK-004 的已有实现。

### 2. 单项结果模型

使用冻结泛型数据类 `ItemResult[R]` 表示一项处理结果，至少包含：

- `index: int`：该项在输入序列中的原始位置。
- `status`：只能表示成功或失败两种状态。
- `value: R | None`：成功时保存 worker 返回值；worker 合法返回 `None` 时仍属于成功。
- `error: Exception | None`：失败时保存捕获到的原异常对象。

状态用于区分“成功返回 `None`”和“执行失败”。结果创建后不可修改。

### 3. 异步批处理入口

提供异步函数 `async_map_limited`，它应：

- 接收输入序列 `items`。
- 接收异步 worker；worker 每次接收一项输入并返回可等待结果。
- 接收 `max_concurrency`，表示允许同时执行的最大 worker 数量。
- 返回与输入等长的 `list[ItemResult[R]]`。
- 使用类型标注表达输入类型、worker 参数类型与结果类型之间的关系。

### 4. 并发与顺序语义

- 所有输入最终都恰好交给 worker 一次。
- 同时位于 worker 执行区间内的调用数量不得超过 `max_concurrency`。
- 当输入数量大于 1 且并发上限大于 1 时，不能通过逐项 `await worker(item)` 退化为完全串行处理。
- 输出列表必须按照输入顺序排列，即使 worker 的完成顺序不同。
- 每条结果的 `index` 必须与原输入位置一致。
- 空输入返回空列表，并且不调用 worker。

### 5. 失败隔离

- worker 成功时，结果状态为成功，`value` 保存原始返回值，`error` 为 `None`。
- worker 抛出普通 `Exception` 时，结果状态为失败，`value` 为 `None`，`error` 保存同一个异常对象。
- 一项失败不能阻止其他输入执行完成；批处理函数不因普通单项异常整体抛出。
- 不捕获或转换 `BaseException`；外部取消不应被包装成普通失败结果。

### 6. 参数验证

- `max_concurrency` 必须是大于等于 1 的整数，布尔值不合法。
- 参数非法时立即抛出包含字段原因的 `ValueError`，不得调用 worker。
- 即使输入为空，也必须先验证 `max_concurrency`。

## 约束

- 生产代码只使用 Python 标准库；测试可以使用 pytest。
- 不使用线程、进程、`ThreadPoolExecutor` 或 `ProcessPoolExecutor`。
- 不使用第三方异步库或限流库。
- 不使用 `time.sleep`；测试也不通过真实等待时长判断并发。
- 不实现重试、超时、速率限制、优先级或动态调整并发数。
- 不要求安装 `pytest-asyncio`；测试可以在普通 pytest 测试函数中使用 `asyncio.run`。
- 不在模块导入时创建事件循环、任务或输出内容。
- 测试应观察公开行为，不依赖私有变量或具体任务容器。

至少覆盖以下测试：

- [ ] 单项成功。
- [ ] 多项成功，输出值和索引正确。
- [ ] 使用受控事件或协程让完成顺序与输入顺序不同，验证输出顺序。

## 边界情况

- `max_concurrency=1` 时行为等价于受控串行执行，但仍使用同一异步接口。
- 并发上限大于输入数量。
- 输入中包含同一个可变对象多次，worker 每次应收到对应的原对象。
- 多项同时失败，每个失败结果分别保存对应异常。
- worker 返回的值本身是一个 `Exception` 对象；只要它是正常返回，就必须记录为成功值，不能误判为执行失败。
