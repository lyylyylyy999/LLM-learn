## 背景

TASK-007 已经能够让 DeepSeek 返回经过 JSON Schema 和 Pydantic 验证的结构化对话分析结果，但一次成功调用不能说明模型是否提取了对话中的必要信息。

本任务只完成评测的最小闭环：保存 3 条固定合成对话，为每条对话定义少量必要概念，然后使用确定性规则判断一份 `AnalysisResult` 是否覆盖这些概念。重点是理解“固定样例、期望结果、评分规则”三者的关系，不在本任务中搭建完整评测平台。

## 学习目标

完成后，学习者应该能够：

- [ ] 解释单元测试、真实冒烟测试和模型评测的区别。
- [ ] 使用 Pydantic 为固定评测样例定义可验证的数据契约。
- [ ] 使用简单、可解释的规则评估结构化模型输出。
- [ ] 说明关键词规则评测能发现什么，以及不能证明什么。

## 前置知识

- 复习 TASK-007 的 `AnalysisResult`，本任务必须直接复用它。
- 复习 JSONL 逐行读取和 Pydantic 验证。
- 理解子串匹配、`casefold()` 和连续空白归一化。

开始编码前，用一个小例子手算：期望概念的可接受短语是 `["early stopping", "提前停止"]`，模型输出包含“建议使用提前停止”，该概念是否命中，以及为什么。

## 功能要求

### 1. 项目结构

- 实现放在 `exercises/task_008_llm_evaluation/`。
- 测试放在 `tests/test_task_008/`。
- 固定评测集放在 `evals/task_008/cases.jsonl`。
- 不复制 TASK-007 的结构化输出模型，直接导入并复用 `AnalysisResult`。

### 2. 固定评测集

创建恰好 3 条公开合成对话，分别覆盖：

1. 只有知识解释，没有行动项。
2. 有一个明确行动项。
3. 有多个关键事实和多个行动项。

每条 JSONL 记录至少包含：

- 唯一且非空的 `case_id`。
- 非空的 `conversation`。
- 摘要、关键点和行动项各自需要覆盖的期望概念。

每个期望概念至少包含：

- 非空的可读名称。
- 1–3 个非空的可接受短语；命中任意一个短语即视为覆盖该概念。

使用 Pydantic 拒绝缺失字段、额外字段、空白文本和空的可接受短语。加载完整文件时还必须拒绝重复 `case_id`。样例不得包含真实个人信息或私有对话。

### 3. 加载评测集

提供一个公开加载函数：

- 接收 JSONL 文件路径。
- 跳过纯空行。
- 按行解析并使用 Pydantic 验证。
- 返回保持文件顺序的评测 case 列表。
- JSON 无效、Schema 不合法或 ID 重复时抛出专门的评测数据异常。
- 异常至少包含文件行号或重复 ID，但不得把完整对话写入异常或日志。

### 4. 文本归一化与概念匹配

实现一个小型、确定性的匹配规则：

- 使用 `casefold()` 处理大小写差异。
- 把连续空白归一化为一个普通空格，并去除首尾空白。
- 不修改原始评测 case 或模型结果。
- 某个可接受短语是对应模型字段的子串时，该概念命中。
- 摘要概念只能在 `summary` 中匹配。
- 关键点概念只能在 `key_points` 合并后的文本中匹配。
- 行动项概念只能在 `action_items` 合并后的文本中匹配。

### 5. 单个 case 评分

提供一个纯函数，接收一个评测 case 和一个 TASK-007 `AnalysisResult`，返回不可变的结构化评分结果。至少包含：

- 三类概念各自的期望数量和命中数量。
- 三类概念各自的覆盖率；期望数量为零时使用 `None`，不能除零或伪造 100%。
- `no_action_items_correct`：仅当期望行动项为空时有布尔值，否则为 `None`。
- `passed`：摘要和关键点概念全部命中，并且：
  - 有期望行动项时，所有行动项概念均命中；
  - 没有期望行动项时，模型必须返回空 `action_items`。

评分函数不得调用模型、读取环境变量、修改文件或记录原始对话。

## 约束

- 不实现多个 case 的聚合报告。
- 不实现 token、延迟或成本统计。
- 不实现两次运行的报告比较。
- 不调用真实 DeepSeek API，不新增真实集成测试。
- 不使用另一个 LLM 作为裁判，不使用嵌入、ROUGE、BLEU、pandas、NumPy 或第三方评测框架。
- 不实现并发、重试、缓存、数据库、Web API、RAG 或工具调用。
- 不修改 TASK-007 的公开行为来迁就评测器。

## 验收标准

- [ ] 3 条固定合成样例通过验证，ID 唯一，并覆盖规定场景。
- [ ] 非法 JSON、非法字段和重复 ID 产生明确且安全的评测数据异常。
- [ ] 大小写和连续空白不影响概念匹配。
- [ ] 三类概念只在各自字段中匹配，不发生跨字段误命中。
- [ ] 单个 case 的命中数、覆盖率、无行动项判断和最终通过状态符合手算结果。
- [ ] 默认测试完全离线。
- [ ] 全量 pytest、Ruff 和 mypy 检查通过。

## 边界情况

- JSONL 文件为空或只有空行。
- `case_id` 只包含空白或重复出现。
- 可接受短语只包含空白。
- 同一概念的多个可接受短语同时出现，只能记一次命中。
- 期望行动项为空，但模型生成了行动项。
- 合法的语义等价表达没有包含任何预设短语，因此规则评分未命中。
