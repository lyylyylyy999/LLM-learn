# TASK-008 — 版本化 LLM 回归评测器

- **难度：** L2
- **预计有效编码时间：** 150–180 分钟
- **开发分支：** `develop`
- **状态：** 进行中
- **任务设计基线：** `5986d80`
- **实现审查基线：** 本任务说明提交；开始编码前记录其提交哈希

## 背景

TASK-007 已经能够通过 DeepSeek 返回经过 JSON Schema 和 Pydantic 双重验证的结构化对话分析结果，但一次成功的冒烟测试只能说明调用链可用，不能说明模型在不同类型的对话上是否持续提取了正确的摘要、关键点和行动项。

本任务建立一个小型、版本化、可重复运行的回归评测器。它使用公开的合成对话和人工定义的必要概念，通过确定性规则评估结构成功率、概念覆盖率、无行动项判断、延迟、token 和估算成本。目标不是构造一个“完美评分器”，而是学会把模型行为转化为可复查的数据和指标，并明确规则评测的能力边界。

## 学习目标

完成后，学习者应该能够：

- [ ] 解释单元测试、真实冒烟测试和回归评测分别解决什么问题。
- [ ] 使用版本化样例、期望概念和确定性匹配规则评估非确定性模型输出。
- [ ] 正确聚合成功率、概念覆盖率、延迟、token 和估算成本，并说明缺失数据对指标的影响。
- [ ] 比较两份评测报告的指标差异，而不是只凭单个输出判断效果好坏。

## 前置知识

- 复习 TASK-007 的 `AnalysisResult`、`AnalysisResponse`、异常分类和真实 smoke 测试开关。
- 理解比率的基本计算方式，以及“分母为零”和缺失 usage 不能被默认为零。
- 理解规则匹配只能检查预先列出的概念，不能等价于完整的语义正确性或忠实度评估。
- 阅读 [DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)；价格可能变化，只能作为运行时配置和报告中的带日期假设，不能硬编码在业务逻辑中。

开始编码前，用一个不超过 10 分钟的小实验手算：一个期望概念有两个可接受短语，其中一个出现在模型结果中时如何记分；usage 缺失时为什么不能把 token 和成本记为零。

## 功能要求

### 1. 项目结构与复用边界

- 评测实现放在 `exercises/task_008_llm_evaluation/`。
- 默认离线测试放在 `tests/test_task_008/`。
- 固定评测集和评测报告放在 `evals/task_008/`。
- 必须复用 TASK-007 的 `AnalysisResult`，不得复制一份字段相同但独立演化的结构化输出模型。
- 使用现有依赖和标准库完成基础任务，不新增 pandas、NumPy、LLM 评测框架或数据库。

### 2. 版本化评测集

创建一个包含 4–6 条公开合成对话的 JSONL 评测集。样例至少覆盖：

- 没有行动项的解释性对话。
- 有一个明确行动项的对话。
- 有多个关键事实和多个行动项的对话。
- 容易把建议、问题或假设误判为行动项的对话。

每条样例至少包含：

- 唯一且非空的 `case_id`。
- 非空 `conversation`。
- 需要在摘要、关键点和行动项中分别覆盖的期望概念。
- 每个期望概念包含一个便于阅读的名称，以及 1–3 个非空的可接受短语；命中任意一个短语即可视为覆盖该概念。

评测集必须由 Pydantic 验证，并拒绝重复 ID、空白文本、空的可接受短语、字段缺失和额外字段。数据内容不得包含真实个人信息、API Key 或私有对话。

### 3. 单次评测记录

为每个 case 建模一次评测记录，至少包含：

- `case_id`。
- 成功时的 `AnalysisResult`，或失败时的稳定失败类别；两者必须且只能存在一个。
- 模型名和提示词版本标签。
- 可空的 input、output、total token。
- 非负耗时。

记录集合必须与评测集 case 一一对应。重复、缺失或未知 `case_id` 应抛出明确的数据错误，不能静默忽略或改变分母。

### 4. 确定性评分规则

实现纯离线评分，不调用模型：

- 匹配前至少执行大小写无关处理和连续空白归一化，不修改原始评测数据。
- 摘要概念只在摘要中匹配，关键点概念只在 `key_points` 中匹配，行动项概念只在 `action_items` 中匹配。
- 一个概念的任一可接受短语出现在对应字段时，该概念记为命中。
- 单项概念覆盖率为“命中概念数 / 期望概念数”。
- case 通过要求结构成功且所有期望概念均命中。
- 对期望行动项为空的 case，只有模型返回空 `action_items` 才通过无行动项检查；不能因为分母为零而自动给出虚假的行动项覆盖率。
- 模型失败的 case 结构成功记为失败，且不能伪造一份空 `AnalysisResult` 参与评分。

### 5. 聚合报告

生成不可变的结构化评测报告，至少包含：

- 数据集版本、模型名和提示词版本。
- case 总数、结构成功率和 case 通过率。
- 摘要、关键点和行动项的概念覆盖率。
- 无行动项判断准确率；当评测集中没有此类 case 时使用 `None`，不能除零。
- 平均耗时；明确它使用哪些记录作为分母。
- 已知 input、output、total token 合计，以及 usage 覆盖率。
- 基于运行时价格配置计算的“已知 usage 估算成本”。报告必须同时保存价格标签或假设，不能把估算成本描述成精确账单。

价格配置必须验证非负值。usage 缺失时仍可生成报告，但 usage 覆盖率必须反映缺失，成本只能基于已知 usage 计算。

### 6. 报告比较

提供一个比较两个报告的纯函数：

- 只有数据集版本和 case 数一致时才允许比较，否则明确失败。
- 返回结构成功率、case 通过率、三类概念覆盖率、平均耗时和已知 usage 估算成本的差值。
- 不自动宣称某个报告“更好”；质量、延迟和成本可能存在取舍，应由调用者解释。

### 7. 真实评测验证

- 增加默认跳过的 DeepSeek 评测集成测试或受控脚本，显式开关使用 `RUN_DEEPSEEK_EVAL=1`。
- 仅使用版本化公开样例，并限制为本任务的 4–6 个 case。
- Key、模型名和价格假设来自环境变量；缺失必要配置时显式开启的评测应清楚失败。
- 复用 TASK-007 的真实分析函数。结构化输出失败可以记录为失败 case；认证、连接或配置错误应让真实评测明确失败，不能伪装成质量问题。
- 默认 pytest 不访问网络。真实评测不写回或覆盖版本化评测集。
- 在 `evals/task_008/REPORT.md` 中记录最终实现的实际命令、日期、数据集版本、模型、提示词版本、价格假设和脱敏聚合指标。不要记录 Key、完整对话或完整模型输出。

## 约束

- 不使用另一个 LLM 作为裁判，不使用嵌入相似度、ROUGE、BLEU 或第三方评测框架。
- 不为提高分数修改评测期望以迎合某次模型输出；评测集变化必须提升数据集版本并说明原因。
- 不在业务代码中硬编码 DeepSeek 价格；价格必须是运行时输入，并在报告中记录来源日期和假设。
- 不实现并发、重试、缓存、数据库、Web API、RAG 或工具调用。
- 不修改 TASK-007 的公开行为来迁就评测器；评测层依赖分析模块，而不是反向污染分析模块。
- 不提交真实 Key、原始私有数据或未经脱敏的外部响应标识。

## 边界情况

- 可接受短语只包含空白，或者不同概念共享同一个短语。
- 模型使用不同大小写或在词语间加入多余空白。
- 期望行动项为空，但模型凭空生成行动项。
- 所有 case 都失败，或者所有成功记录都缺少 usage。
- input、output 或 total token 只有部分字段缺失或彼此不一致。
- 两次运行使用了不同数据集版本、不同 case 数或不同价格假设。
- 真实模型返回合法结构，但规则评测无法识别语义等价表达。
