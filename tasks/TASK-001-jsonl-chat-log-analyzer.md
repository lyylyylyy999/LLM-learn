# TASK-001 — JSONL 对话日志分析器

- **难度：** L2
- **预计有效编码时间：** 90–150 分钟
- **建议分支：** `learn/task-001-jsonl-chat-log-analyzer`
- **状态：** 待确认

## 背景

LLM 应用通常会产生对话日志、评测样本和请求记录。JSONL 适合逐条保存这类数据，但真实文件可能包含空行、格式错误或字段不合法的问题。

本任务要求实现一个小型日志分析模块：逐行读取 JSONL 对话记录，验证数据，将合法消息转换为明确的数据模型，计算汇总指标，并把结果写入 JSON 文件。它是后续日志分析、评测数据集处理和 RAG 文档流水线的基础练习。

## 功能要求

### 1. 项目位置

实现代码放在首次实现时创建的 `exercises/task_001_jsonl_chat_log_analyzer/` 目录中。保持结构最小，只创建完成本任务实际需要的模块和测试文件。

### 2. 输入格式

输入文件使用 UTF-8 编码，每个非空行必须是一个 JSON 对象，并包含以下字段：

- `conversation_id`：非空字符串。
- `role`：只能是 `system`、`user` 或 `assistant`。
- `content`：非空字符串；只包含空白字符也视为非法。

空行或只包含空白字符的行应被忽略，不计入统计。

### 3. 数据模型

- 使用数据类表示一条合法消息。
- 使用另一个数据类表示统计结果。
- 数据模型的字段应具有明确类型，不使用无约束的 `Any` 逃避类型设计。

### 4. 读取与验证

- 提供一个生成器函数，接收 `str` 或 `Path` 类型的输入路径，逐条产出合法消息。
- 必须逐行迭代文件，不得使用 `read`、`read_text` 或等价方式一次性读取整个文件。
- 遇到非法 JSON、非对象 JSON、字段缺失、字段类型错误、非法角色或空内容时，抛出自定义异常 `InvalidMessageError`。
- 异常信息必须包含出错的原始文件行号和可理解的失败原因，但不得包含完整文件内容。
- 输入文件不存在时，保留标准的 `FileNotFoundError` 行为，不要将其伪装成数据格式错误。

### 5. 统计

汇总结果至少包含：

- `total_messages`：合法消息总数。
- `conversation_count`：不同 `conversation_id` 的数量。
- `messages_by_role`：三个合法角色各自的消息数量；数量为 0 的角色也必须出现。
- `total_characters`：所有消息原始 `content` 的字符数之和。

统计逻辑应接收可迭代的消息对象，不直接依赖文件路径。

### 6. 输出

- 提供一个组合入口，接收输入路径和输出路径，完成读取、统计与写入。
- 输出为 UTF-8 编码的 JSON 对象，字段名称与统计要求一致。
- 中文内容必须保持可读，不应被写成 `\uXXXX` 形式。
- 空输入文件应正常生成全零统计结果，而不是报错。
- 如果输入包含非法记录，不得创建新的输出文件；如果输出文件已存在，其原内容必须保持不变。

## 约束

- 生产代码只使用 Python 标准库；测试可以使用 pytest。
- 不使用 pandas、Pydantic、第三方 JSONL 库或命令行框架。
- 不实现 FastAPI、数据库、异步处理或 LLM API 调用。
- 所有公开函数和数据类字段必须有明确类型标注。
- 不要求命令行界面；核心目标是数据建模、职责拆分、异常和测试。
- 不复制网上的完整实现；遇到问题时按提示 1、提示 2、提示 3 的顺序请求帮助。

## 边界情况

- 文件开头、中间或结尾存在空行。
- 非法记录出现在多条合法记录之后，异常行号仍必须对应原始文件。
- 多条消息使用相同 `conversation_id`。
- 某些合法角色在输入中没有出现。
- `content` 包含中文、换行转义、表情符号或前后空格。
- 输入文件和输出文件路径相同。此情况应明确拒绝，并保证原文件不变。
