# TASK-003 — 类型安全的重试装饰器

- **难度：** L2
- **预计有效编码时间：** 90–150 分钟
- **建议分支：** `learn/task-003-retry-decorator`
- **状态：** 待确认

## 背景

TASK-002 已经提供了同步重试执行器，但调用者每次都要手动构造无参数操作并调用 `execute_with_retry`。在真实客户端代码中，重试通常以装饰器形式复用，同时还必须支持原函数的位置参数、关键字参数、返回类型和元数据。

本任务要求在不复制重试循环的前提下，为 TASK-002 增加一个同步重试装饰器。重点不是再次实现重试，而是理解装饰器的闭包层级、参数转发、类型传播、函数元数据和测试边界。

## 学习目标

完成后，学习者应该能够：

- [ ] 解释装饰器工厂、装饰器和包装函数三层调用关系。
- [ ] 使用 `ParamSpec`、`TypeVar` 和 `Callable` 保留被装饰函数的参数及返回类型。
- [ ] 使用 `functools.wraps` 保留函数名称、文档字符串等元数据。
- [ ] 复用已有 `execute_with_retry`，避免产生第二套重试规则。
- [ ] 使用 Mock 验证参数转发、重试次数、等待行为和异常边界。

## 前置知识

- 装饰器语法 `@decorator` 与手动赋值 `func = decorator(func)` 的等价关系。
- 闭包如何保存 `RetryPolicy` 和等待函数。
- `*args`、`**kwargs` 的接收与转发。
- `functools.wraps` 的用途。
- `ParamSpec` 表达可调用对象参数列表，`TypeVar` 表达返回类型。

建议先完成三个最小实验：

1. 写一个只打印函数名的简单装饰器，并手动展开装饰过程。
2. 给带有位置参数和关键字参数的函数套一层包装，确认参数能够原样转发。
3. 对比使用和不使用 `functools.wraps` 时函数的 `__name__` 与 `__doc__`。

## 功能要求

### 1. 项目位置

在 `exercises/task_002_retry_executor/` 中新增装饰器模块，复用现有的 `RetryPolicy` 和 `execute_with_retry`。TASK-002 的公开行为必须保持兼容。

TASK-003 的测试放在 `tests/test_task_003/` 中，不把新测试混入 TASK-002 的测试文件。

### 2. 公开装饰器

提供公开装饰器工厂 `retry`，它应：

- 接收一个 `RetryPolicy`。
- 支持注入等待函数，生产环境默认使用 `time.sleep`。
- 能装饰接收任意位置参数和关键字参数的同步函数。
- 返回值与被装饰函数的原始返回值保持一致，包括对象身份。
- 使用 `ParamSpec` 和 `TypeVar` 表达包装前后参数类型及返回类型保持一致。

### 3. 复用已有执行器

- 每次调用包装函数时，都必须通过 TASK-002 的 `execute_with_retry` 完成重试。
- 不得在装饰器模块中复制 `for`、`while` 或递归形式的重试循环。
- 可重试异常、不可重试异常、等待次数、日志和 `RetryExhaustedError` 的语义以 TASK-002 为唯一实现来源。
- 装饰器本身不额外配置 logger，也不重复记录重试日志。

### 4. 参数与调用行为

- 每次尝试都使用本次调用包装函数时收到的同一组位置参数和关键字参数。
- 不修改传入的参数容器或业务对象。
- 同一个装饰后函数可以被调用多次；每次调用的尝试次数必须独立，不能残留上一次调用的状态。
- 装饰实例方法时，`self` 必须能够正常转发。

### 5. 元数据

装饰后的函数至少应保留原函数的：

- `__name__`
- `__doc__`
- `__wrapped__`

## 约束

- 生产代码只使用 Python 标准库；测试可以使用 pytest。
- 必须复用 TASK-002 的公开接口，不修改其核心重试循环来迁就装饰器。
- 不使用第三方重试或装饰器库。
- 不实现异步装饰器、指数退避、随机抖动、缓存或超时控制。
- 不使用装饰器类；本任务重点是函数、闭包和 `functools.wraps`。
- 不捕获或转换 TASK-002 之外的新异常。
- 所有公开接口必须有明确类型标注。
- 测试中禁止真实等待。

## 验收标准

- [ ] 无参数函数和带参数函数都能被装饰并正常调用。
- [ ] 第一次成功时只调用原函数一次，不调用等待函数。
- [ ] 可重试异常后成功时，返回最终结果，原函数调用次数和等待行为正确。
- [ ] 重试耗尽时仍抛出 TASK-002 的 `RetryExhaustedError`，属性和异常链没有丢失。
- [ ] 不可重试异常保持同一个异常对象向外传播。
- [ ] 位置参数、关键字参数和实例方法的 `self` 均能正确转发。
- [ ] 可变返回对象保持对象身份，不被复制。
- [ ] 多次调用装饰后函数时，重试状态相互独立。
- [ ] `__name__`、`__doc__` 和 `__wrapped__` 均得到保留。
- [ ] 在仓库根目录执行 `python -m pytest -q` 时全部测试通过。

## 测试要求

至少覆盖以下测试：

- [ ] 无参数函数第一次成功。
- [ ] 同时包含位置参数和关键字参数的函数，且每次重试收到正确参数。
- [ ] 前两次抛出可重试异常、第三次成功；验证调用次数以及等待的次数和参数。
- [ ] 重试耗尽，并验证 `attempts`、`last_error` 和 `__cause__`。
- [ ] 不可重试异常立即原样传播，验证异常对象身份。
- [ ] 可变返回对象保持同一对象。
- [ ] 连续调用同一个装饰后函数，一次发生重试、另一次立即成功，状态不串联。
- [ ] 装饰实例方法后能够正常访问实例状态。
- [ ] 函数元数据得到保留。

测试应验证可观察行为，不依赖装饰器内部闭包变量或精确的内部实现结构。

## 边界情况

- 被装饰函数返回 `None`。
- 位置参数或关键字参数本身是可变对象。
- 被装饰函数没有文档字符串。
- 同一 `RetryPolicy` 被多个装饰器使用；策略只读使用，不应被装饰器修改。
- 被装饰函数执行失败前可能已经产生外部副作用；装饰器不能自动保证幂等性。
