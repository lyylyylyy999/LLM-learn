# AI 应用工程训练仓库

这是一个面向 AI 应用工程师实习能力的长期工程训练仓库。它不是课程笔记集合，也不是一次性演示项目：这里用小型、可验证的编码任务，持续训练 Python 工程、后端开发、LLM 应用、RAG、智能体、测试与生产工程能力。

目标是在 2027 年初具备 AI 应用开发实习所需的基本独立交付能力：能理解需求、做出设计取舍、实现和调试功能、编写测试、使用 Git 协作，并能评估 LLM 系统的质量、延迟与成本。

## 学习方式

训练采用短反馈循环：

> 最少必要知识 → 编码任务 → 独立实现 → 测试与调试 → 代码审查与修改 → 最终审查 → 针对性提问 → 复盘

每个正式任务原则上控制在 30 分钟到 3 小时有效编码时间。基础知识会嵌入真实功能，而不是等 Python、后端开发全部学完后才开始 AI 项目。难度从 L1/L2 起步，根据代码审查和每周复盘的证据逐步提升到 L3/L4。

导师协作规则见 [AGENTS.md](AGENTS.md)，阶段路线见 [ROADMAP.md](ROADMAP.md)。

## Git 工作流程

- `develop` 是训练主分支。
- 正式任务开始前，导师建议分支名，例如 `learn/task-003-fastapi-user-api`；由学习者决定并创建分支。
- 一个分支聚焦一个任务，提交信息使用 Conventional Commits 约定，例如 `feat: add user creation endpoint`、`test: cover duplicate email handling`。
- 代码审查时优先检查任务分支相对 `develop` 的差异。
- 不自动推送、合并或提交，不改写已有历史；除非学习者明确要求对应操作。
- 不使用 `update`、`修改`、`fix bug` 等缺少信息的提交信息。

## 如何开始任务

1. 请求导师基于 [ROADMAP.md](ROADMAP.md)、最近的代码审查和每周复盘创建下一个任务。
2. 导师使用[任务模板](tasks/templates/task-template.md)给出学习目标、约束、验收标准和测试要求，但默认不提供完整实现。
3. 确认当前从最新 `develop` 开始，并由学习者决定是否创建建议的任务分支。
4. 学习者独立实现；遇到困难时依次请求提示 1、提示 2、提示 3，只有明确请求完整解答时才获取完整答案。
5. 使用验收标准和测试自检后，请求代码审查。

## 如何请求代码审查

提交代码审查请求时，说明任务编号、当前分支、已运行的测试、已知问题和最不确定的设计决策。导师会基于当前分支相对 `develop` 的差异，按以下维度反馈：

- 严重问题
- 主要问题
- 次要问题
- 缺失的测试
- 合理的设计
- 最终审查后的针对性问题

中间审查只围绕实际问题推动修复。代码通过最终审查后，导师再根据最终实现和修改过程提出 3–5 个针对性问题，确认学习者能解释设计原因、失败场景和测试策略。

## 如何完成复盘

代码通过最终审查后，导师会提出 3–5 个针对性问题，并依据 diff、测试和审查记录起草“本次所学、关键错误及原因”等有证据支持的内容。学习者核对和补充这些内容，并独立回答针对性问题，双方使用[任务复盘模板](retrospectives/task-retrospective-template.md)共同定稿。L1/L2 使用 5–10 分钟简版，L3 以上使用完整版。任务复盘不记录下一步行动；任务与复盘完成后直接进入下一个任务。每周使用[每周复盘模板](weekly/weekly-review-template.md)，依据提交记录、已完成任务、测试和代码审查证据调整路线。
