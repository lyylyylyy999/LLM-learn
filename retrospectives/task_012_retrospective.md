## 本次所学（共同确认）

- 批量统计要区分“评分未通过”和“本次没有有效结果”：前者仍计入 `scored_cases`，后者计入 `failed_cases`；两者都在总体通过率的分母中。
- 样例 ID 与结果 ID 必须逐一对应。两个集合元素数量相同，仍可能一边缺少某个 ID、另一边多出别的 ID；应在逐条评分之前拒绝这种输入不一致。
- 离线批量测试只验证已有 `AnalysisResult` 的评分、报告结构与脱敏，不能证明真实模型调用的行为。

## 关键错误（共同确认）

- **错误：**初版只比较 `cases` 和 `outcomes` 的数量。两边 ID 数量相同但成员不同的输入在访问缺失 ID 时抛出 `KeyError`，不符合合同要求的安全 `ValueError`。
  **代码层面原因：**把“数量相等”当成“ID 完全对应”，在进入逐条评分前没有验证每个样例 ID 都存在于结果映射中。
- **错误：**初版导入顺序不符合 Ruff 检查。
  **代码层面原因：**生产文件中第三方库和仓库模块的导入分组顺序不符合当前规则；后续已修正。

## 最终审查问题（学习者回答与导师补充）

### 1. 为什么只比较两侧 ID 的数量，无法发现上轮的缺失与多余 ID 问题？

**学习者回答：**数量一致不能保证 ID 完全一致。

**导师补充：**例如 `cases` 包含 `first、second`，`outcomes` 包含 `first、extra`；数量均为二，但缺少 `second` 且多出 `extra`。映射键本身不会重复。

### 2. 三条样例分别为评分通过、评分未通过、执行失败时，各计数和通过率是多少？

**学习者回答：**`scored_cases=2`、`failed_cases=1`、`passed_cases=1`、`pass_rate=1/3`。只要完成评分就计入 `scored_cases`，没有评分计入 `failed_cases`，通过数由评分结果决定。

### 3. 没有预期行动项时，如果模型生成了行动项，如何影响批量通过数？

**学习者回答：**`passed` 会变成 `False`，批量通过数依据 `passed` 统计，因此不会增加。

**导师补充：**单条评分中的 `no_action_items_correct` 为 `False`，进而使 `passed=False`。

### 4. 本任务测试为什么不需要模型 Mock？脱敏测试如何避免空断言？

**学习者回答：**本任务不涉及模型调用，因此无需模型 Mock。脱敏测试把一个标记放进 `case.conversation`，另一个放进 `AnalysisResult.summary`；检查逐条分数确实由现有评分器对传入结果算出，确认结果经过评分路径；再检查序列化报告中没有这两个标记。

**导师补充：**这些断言验证了报告的评分路径和脱敏边界，不能证明真实模型或 SDK 行为。
