## 最终审查问题（学习者回答，导师确认）

### 1. 非法输入为什么不会覆盖已有输出？

假设输入文件前两行合法、第三行非法，并且输出文件已经存在。请按照 `main`、`read_jsonl` 和 `statistical_data` 的实际调用顺序，说明异常在什么时候发生、输出文件为什么能够保持原内容。

**回答：**`main` 先调用 `read_jsonl` 创建生成器，但此时还没有真正读取文件。`statistical_data` 迭代这个生成器时，`read_jsonl` 才开始逐行执行；前两行正常参与统计，第三次循环读取到非法 JSON 后抛出 `InvalidMessageError`。异常会从 `statistical_data` 继续传播并中断 `main`，程序尚未执行后面的目录创建和输出文件写入，因此已有输出文件保持原内容。

### 2. 当前实现的时间和空间复杂度是什么？

假设共有 `n` 条合法消息、`u` 个不同的 `conversation_id`。请说明统计过程的时间复杂度和额外空间复杂度，并解释在什么情况下“使用生成器”仍然会失去流式处理的内存优势。

**回答：**统计过程需要遍历全部 `n` 条消息，所以时间复杂度是 O(n)。集合 `conversation_ids` 最多保存 `u` 个不同的会话编号，因此额外空间复杂度是 O(u)。如果消费者调用 `list(generator)` 保存全部消息，即使读取端使用生成器，额外空间仍会增长为 O(n)，从而失去流式处理的内存优势。

### 3. 如何避免测试假阳性和相互污染？

结合本任务曾经出现的测试问题，说明为什么必须在调用后重新读取输出文件，以及 `tmp_path` 如何避免测试结果依赖仓库中的遗留文件或测试执行顺序。

**回答：**为了证明已有输出没有被修改，需要在调用前读取并保存原内容，在调用发生异常后重新读取同一个输出文件，再比较两次内容。只断言调用前保存在变量中的值无法反映文件之后是否被改变。`tmp_path` 会为每个测试提供独立目录，使测试不依赖仓库中的遗留文件，也不会因为其他测试使用了相同路径而受到执行顺序影响。

### 4. 三类异常的职责边界是什么？

分别说明非法 JSON、输入文件不存在、消息字段或业务规则不合法时应该暴露什么异常；再解释 `raise ... from e` 对调试有什么价值。

**回答：**非法 JSON 最初触发 `JSONDecodeError`，但它会被捕获并最终转换为 `InvalidMessageError`；输入文件不存在时保留 `FileNotFoundError`；字段缺失、字段类型错误或业务规则不合法时最终暴露 `InvalidMessageError`。`raise ... from e` 会把原始异常保留为新异常的直接原因，形成异常链，调试时可以同时追踪底层错误和业务层错误。
