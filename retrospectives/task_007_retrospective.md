  **原因：**测试最初只验证正确实现能够通过，没有确认错误实现是否也能通过；修改请求 Schema 后也没有立即把真实运行记录视为需要重新生成的测试证据。

## 最终审查问题（学习者回答，导师确认）

### 1. 服务端已经使用 JSON Schema，为什么还需要本地验证？

**回答：**大模型生成的内容不一定完全正确，因此客户端仍需要在本地验证。服务端 Schema 可以降低格式错误概率，但本地 Pydantic 验证才是应用接收外部数据时的最终边界。

### 2. 为什么不能只使用 `min_length=1`，还需要 `pattern=r"\S"`？

**回答：**`min_length=1` 只检查字符数量，纯空白字符串的长度同样可以大于等于 1；`pattern=r"\S"` 要求字符串中至少存在一个非空白字符。`min_length` 和 `pattern` 会进入 JSON Schema，`strip_whitespace=True` 则在本地验证时去除首尾空白。

### 3. 为什么不同异常采用不同传播方式？

**回答：**SDK 认证、连接和限流等异常需要保持原样，避免丢失上层进行分类处理所需的信息。Pydantic 验证错误属于应用识别出的结构化输出失败，因此包装成统一的 `StructuredOutputError`；同时使用异常链保留原始 `ValidationError`，兼顾稳定的业务边界和底层诊断信息。

### 4. Mock 测试和真实 smoke 测试分别证明什么？

**回答：**Mock 测试可以低成本、快速且稳定地模拟模型响应，验证请求参数、结果映射和各种失败分支，但不能证明真实服务能够成功调用。真实 smoke 测试用于至少验证一次 SDK、API 地址、认证、模型配置、最终 JSON Schema 和实际响应结构能够协同工作，但不适合作为每次默认测试，也不能穷举所有业务边界。
