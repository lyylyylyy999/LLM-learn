## 本次所学（共同确认）

- 第三方 SDK 的超时异常应先转换为领域异常，再由 HTTP 层映射成稳定、安全的接口响应；这样可以隔离供应商细节，并保持对外合同明确。
- 子类异常必须在父类异常之前捕获。保留原异常作为 `__cause__` 有利于内部调试，但 HTTP 响应不能返回原异常文本，以免泄露供应商信息、请求内容或敏感配置。
- 显式配置超时并关闭 SDK 隐式重试，可以让等待时间、请求尝试次数和费用更容易推断。离线测试能够验证异常转换和接口行为，但不能代替真实网络与模型链路验证。

## 关键错误（共同确认）

- **错误：**最初直接使用任务说明中的描述性文字作为 `504` 响应消息。
  **原因：**把用于说明消息约束的示例内容误认为了实际面向客户端的错误文案。
- **错误：**第一次提交遗漏了运行说明中的超时配置和重试行为。
  **原因：**主要关注代码链路，没有逐项核对任务中的文档要求。

## 最终审查问题（学习者回答）

### 1. 为什么 `LLMTimeoutError` 必须在 `LLMError` 之前捕获？顺序反过来会发生什么？

**学习者回答：**`LLMTimeoutError` 是 `LLMError` 的子类；如果顺序反过来，它会先被 `LLMError` 捕获。

**导师补充：**此时请求仍会收到响应，但会被错误映射为 `502 llm_response_error`，无法进入专门的 `504 llm_timeout` 分支。

### 2. 为什么只判断 `timeout <= 0` 还不能拒绝所有非法浮点值？`NaN` 的比较有什么特殊之处？

**学习者回答：**`timeout <= 0` 不能拒绝 `NaN` 和正无穷。

**导师补充：**`NaN` 与数值进行大小比较时结果为假，正无穷也大于零，因此还需要有限性检查；负无穷本身会被 `<= 0` 拒绝。

### 3. 为什么本任务显式设置 `max_retries=0`？SDK 自动重试会怎样影响总延迟、调用次数和费用？

**学习者回答：**本任务不允许 SDK 自动重试；自动重试会增加总延迟、调用次数和费用。

**导师补充：**SDK 默认在初次失败后最多再重试两次，因此一次业务调用最多可能产生三次请求尝试。关闭隐式重试使当前任务的调用边界和成本更容易推断。

### 4. 保留原异常作为 `__cause__` 对内部调试有什么价值？为什么 HTTP 响应不能包含它？

**学习者回答：**保留原异常可以查看具体异常内容，帮助定位问题；HTTP 响应包含原异常可能泄露敏感信息。

**导师补充：**异常原因还能保留原异常类型、堆栈和上下文；客户端只应收到稳定、脱敏的错误合同。

### 5. 离线超时测试能够证明哪些行为，又不能证明哪些真实情况？

**学习者回答：**离线测试可以证明异常转换、状态码、错误码、调用次数和脱敏，不能证明模型调用的真实行为。

**导师补充：**它也不能证明真实网络中的超时阈值、SDK 实际重试过程、DeepSeek 服务状态或真实调用耗时。
